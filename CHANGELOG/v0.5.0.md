# v0.5.0

Isola is a free and open-source Kubernetes sandbox platform for running untrusted and AI-generated code safely in existing clusters.
One Helm install deploys the whole system onto any cluster with gVisor configured.

## Status

The initial release of Isola comes after many iterations and redesigns to get the APIs just right. It aims to be secure by default and performant. The public APIs may still evolve as adoption grows and new use cases surface; we aim to flag breaking changes in advance and publish migration notes. Whenever possible, we add functionality without breaking existing behavior (e.g. adding CRD fields instead of modifying existing ones) and design for co-existence of older-version sandboxes during upgrades.

Sandboxes run as Kubernetes pods under [gVisor](https://gvisor.dev)'s application kernel. Vulnerability disclosures: see [SECURITY.md](../SECURITY.md).

## Sandbox runtime

Create sandboxes from any OCI image. Configure CPU, memory, and ephemeral storage per sandbox or per container. Set a startup timeout, a total-lifetime timeout, or both. Delete explicitly or let the server reclaim the sandbox automatically.

- **Lifecycle**: `Pending → Running → Terminating → Succeeded|Failed`, observable via CRD status and the REST API.
- **Commands**: run blocking (`run`) or non-blocking (`spawn`). Stream stdout and stderr as output arrives. Supply stdin as a single input or interactively via `write_stdin` / `close_stdin`. Kill, wait, and query exit codes at any time. Per-command `cwd`, `env`, and `timeout_seconds`.
- **Filesystem**: read and write files as text, bytes, or streamed uploads. Parent directories are created automatically.

## Rootfs snapshots

Capture a container's root filesystem changes and restore them into new sandboxes on any node.

- **Storage**: S3, GCS, or Azure Blob Storage. A DaemonSet exposes snapshot tars to gVisor via an NFS mount backed by rclone.
- **On-termination snapshots**: a sandbox can be configured with `termination_policy=SnapshotRootfs(...)` to snapshot automatically before it exits.
- **Resilient restore**: when a sandbox references a snapshot that is not yet visible, the container is restarted until the tar appears or the startup timeout expires.

## Network isolation

Sandboxes have no network access by default: outbound traffic is denied and DNS is sinkholed.

- Allow full internet egress, or restrict egress to a CIDR allowlist.
- Private ranges and cloud metadata endpoints are blocked automatically whenever egress is opened up.
- Opt in to cluster DNS, or provide custom nameservers. When egress is enabled without cluster DNS, public resolvers are injected so that DNS just works.
- Enforced via standard Kubernetes NetworkPolicy. Any CNI that implements policy (EKS, AKS, GKE, Cilium, Calico, etc) works out of the box.

## Multi-container sandboxes

Run multiple containers in a single sandbox. Containers share a network namespace and communicate over localhost. Each container has its own image, command, env, resource limits, and (optionally) restored rootfs snapshot.

## SDK

Currently only a Python SDK is provided.
Other languages can drive the REST API directly via the [OpenAPI spec](../api/openapi/api-gateway.yaml).

## Kubernetes integration

- One Helm chart installs operator, API gateway, and (optionally) the rootfs snapshot infrastructure.
- By default, CRDs are installed as part of the Helm chart install / upgrades.
- Sandboxes live in a dedicated namespace (`isola-sandboxes` by default), separate from the control plane.

## Requirements

- A Kubernetes cluster with a CNI that enforces NetworkPolicy (vanilla, EKS, AKS, GKE, and most others qualify).
- gVisor installed on cluster nodes.
- *(Optional, for snapshots)* An S3, GCS, or Azure Blob Storage bucket.

## Installing

```bash
kubectl create namespace isola-sandboxes
helm install isola oci://ghcr.io/isola-run/charts/isola \
  --namespace isola-system --create-namespace \
  --version 0.5.0
```

Python SDK:

```bash
pip install isola-run==0.5.0
```

See the [README](../README.md) for gVisor setup, snapshot configuration, and deployment options.

## Not yet

- **TypeScript SDK** - planned. Use the REST API in the meantime.
- **Snapshot restore retry on Kubernetes < 1.34** - relies on the `ContainerRestartRules` feature gate (alpha in 1.34, on-by-default in 1.35+). On older clusters, a missing snapshot tar fails the container permanently instead of retrying.
- **Snapshot scope** - only overlay upper-layer changes are captured. Writes to tmpfs mounts (including `/tmp` under gVisor) are not included.
